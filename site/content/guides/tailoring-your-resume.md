The same résumé sent to fifty postings gets the results of a résumé written for none of them. The fix is not fifty rewrites. It is one strong base résumé and a short, repeatable pass per posting, done for the roles you actually want.

## Why it works

Most postings on this board are hosted on Greenhouse, Lever, Ashby or Workday. Those systems parse the résumé into fields and show recruiters a searchable record. A recruiter with two hundred applicants searches and skims for the posting's own words. If the posting says "data pipelines" and your résumé says "ETL", a search misses you, and a skim may too. Tailoring is mostly the work of saying the same true things in the posting's vocabulary.

## The fifteen-minute pass

1. **Read the posting twice.** On the second read, underline the nouns: technologies, systems, domains, methods. Ignore adjectives.
2. **Match each underlined noun to something you have done.** If you have done it and the résumé does not say so, add it, in the posting's word. If you have not, leave it out. Never add a skill you cannot discuss.
3. **Reorder bullets** so the matching ones come first in each entry. Order is free and it changes what a skimmer sees.
4. **Adjust the skills line** to lead with the tools the posting names, in the order the posting names them.
5. **Set the title line** to match the role family if you use one ("Software engineer, new grad 2027" for a software posting, "Data analyst" for an analyst one). Do not use a title you have never held as if you had.
6. **Save as a new file** named for the company, and keep a note of which version went where.

## What not to change

- **Facts.** Dates, titles, employers, degrees, numbers. These are checked.
- **Your strongest project**, even if it is off-topic. A great project shows how you work.
- **Length.** One page for a new graduate. Tailoring should replace, not add.

## Signs of over-tailoring

A résumé that copies the posting's sentences reads as a copy and is discounted. Keywords belong in your own bullets describing your own work. If a posting names eight technologies and you can honestly claim two, claim two well.

## Tracking versions

Mark the job as applied on the board (the `a` key) and record the résumé version in your own tracker. When a recruiter calls a month later, you need to know what they read. [Application strategy](../application-strategy/) covers the tracker.

## When to skip it

Do not tailor for a posting you would not accept. The base résumé is fine for long-shot applications; save the pass for the roles where a callback would matter.
